# IQS / IQSTRC

เว็บแอป PHP สำหรับคัดกรองการสูบบุหรี่ แผนเลิกบุหรี่ E-Learning เกมความรู้ รายงาน และเกียรติบัตร มีหน้าสมาชิกและหน้าผู้ดูแลระบบ

## ติดตั้งไว้ที่ไหน

| รายการ | เครื่องพัฒนา | เซิร์ฟเวอร์ผู้ว่าจ้าง |
| --- | --- | --- |
| ไฟล์เว็บ | `C:\xampp\htdocs\iqstrc\program` | document root ที่ P&T Hosting แจ้ง |
| หน้าสมาชิก | `http://localhost/iqstrc/program/` | P&T Hosting (ปลายทางรอบนี้; ยังไม่ deploy) |
| หน้าแอดมิน | `http://localhost/iqstrc/program/admin/login.php` | P&T Hosting (ปลายทางรอบนี้; ยังไม่ deploy) |
| ฐานข้อมูล | `iqstrc` บน XAMPP | ใช้ค่าที่ P&T Hosting จัดเตรียมไว้ |
| ตั้งค่าฐานข้อมูล | `program/admin/indyEngine/dbStructure.php` | ปรับไฟล์ตั้งค่าบน P&T ให้ตรงกับฐานข้อมูลปลายทาง |

เมื่อได้รับสิทธิ์ P&T Hosting แล้ว ให้วาง **ไฟล์และโฟลเดอร์ข้างใน `program/`** ลง document root ที่ผู้ให้บริการกำหนด ไฟล์ตั้งค่าของเครื่องกับโฮสต์ใช้ค่าคนละชุด ห้ามทับค่าของโฮสต์ด้วยค่าของ XAMPP

ระบบเป็น PHP โดยตรง ไม่ต้องรัน npm หรือ build ก่อนอัป ใช้ PHP ที่รองรับ `mysqli`, `mbstring`, `gd` และ `fileinfo`; ตรวจเวอร์ชัน PHP/MySQL และโฟลเดอร์ document root จากแผงควบคุม P&T ก่อนติดตั้ง

## เปิดในเครื่อง / ติดตั้งใหม่

1. วางโปรเจกต์ไว้ที่ `C:\xampp\htdocs\iqstrc` แล้วเปิด Apache และ MySQL ใน XAMPP
2. สร้างฐานข้อมูล `iqstrc` ใน phpMyAdmin และเลือกฐานนี้ก่อน Import
3. สำหรับฐานว่างที่ต้องการโครงสร้าง P&T ล่าสุด ใช้ `database/pt-hosting-schema-20261116.sql` ซึ่งประกอบด้วย 28 ตารางและ 1 view โดยไม่มีข้อมูลสมาชิก บทเรียน คณะ พื้นที่แบบสำรวจ หรือบัญชีแอดมิน ต้องจัดเตรียมข้อมูลที่จำเป็นแยกต่างหาก ห้ามนำเข้าไฟล์นี้ทับฐานใช้งานจริง
4. `database/iqstrcheal_iqstrc_schema.sql` และ `database/iqstrcheal_iqstrc.safe.sql` เป็นชุดโครงสร้าง/ข้อมูลตัวอย่างเดิม ส่วน `database/migrations/` เป็น migration ทางเลือกที่เคยสร้างสำหรับฐานเดิม มีรายละเอียดชนิดคอลัมน์และ foreign key ต่างจาก snapshot P&T ไม่ต้องรัน migration เหล่านี้หลังนำเข้า snapshot ล่าสุด และห้ามรันกับฐานจริงโดยไม่ตรวจความเข้ากันได้ก่อน
5. การย้ายข้อมูลจริงต้องใช้ไฟล์ SQL ฉบับเต็มที่ส่งมอบแยกแบบส่วนตัว ไม่ใช้ไฟล์ `.safe.sql` แทนข้อมูลจริง และต้องย้าย `program/uploads/` มาด้วย
6. แก้ `$host`, `$db_user`, `$db_password`, `$db_name` ใน `program/admin/indyEngine/dbStructure.php` ให้ตรงกับฐานที่สร้าง ระบบหลักอ่านค่าจากไฟล์นี้ ไม่ใช่จาก `.env`
7. ให้ PHP เขียน `program/uploads/` และ `program/uploads/images/` ได้ และตั้งค่าที่เก็บ session ให้ใช้งานได้ ไม่ต้องเปิดสิทธิ์ `777`
8. เปิดหน้าสมาชิกหรือแอดมินตามตารางด้านบน บัญชีแอดมินให้ใช้บัญชีที่เจ้าของระบบอนุญาต ไม่มีรหัสผ่านระบุใน README

## อัปเดตเว็บจริง

1. แก้และทดสอบใน localhost ก่อน
2. สำรองไฟล์เว็บ ฐานข้อมูล และ `uploads/` บนโฮสต์ก่อนอัป
3. สำหรับรอบนี้ให้ส่งเฉพาะไฟล์เว็บที่เปลี่ยนผ่านช่องทางอัปโหลดของ P&T ไปยัง document root ที่ P&T ยืนยัน ห้ามส่งค่าฐานข้อมูล localhost, ไฟล์ SQL, `.env`, `.git`, `DB/`, `database/`, `deploy/` หรือเครื่องมือทดสอบไปไว้ในเว็บ
4. ถ้ามีรูปใหม่ ให้อัปเพิ่มในตำแหน่งเดิม **ไม่ลบโฟลเดอร์ `uploads/` และไม่ลบรูปเก่าที่ไม่มีในเครื่อง**
5. หากต้องแก้โครงสร้างฐานข้อมูล ให้ใช้ SQL migration เฉพาะจุดหลังสำรอง ห้าม Import ฐานตัวอย่างหรือ dump เก่าทับฐานที่มีสมาชิกใช้งาน
6. ตรวจล็อกอิน สมัครสมาชิก คัดกรอง บันทึกเลิกบุหรี่ E-Learning/ประวัติ วิดีโอ เกม รายงาน เกียรติบัตร และหน้าแอดมินหลังอัป

## ข้อมูลและการดูแล

- ประเภท/ระดับผู้สมัครเก็บใน `user.applicant_type` และ `user.applicant_level`; คณะและมหาวิทยาลัยเก็บใน `user.faculty_id`/`user.university_id` และตาราง `faculty`/`university`
- ประวัติและคำตอบ E-Learning เก็บใน `elearning` (`q1` ถึง `q17`)
- แบบสำรวจเยาวชนใช้ `youth_survey_responses` และตารางเชิงสัมพันธ์ที่เพิ่มด้วย migration; รายงานอ่านจาก view `youth_survey_answer_report`
- ยังเก็บตารางมหาวิทยาลัย/คณะเดิมไว้เพื่อรักษาข้อมูลเก่า ไม่ควรลบเพียงเพราะหน้าสมัครเปลี่ยนแล้ว
- โค้ดสมัครและล็อกอินปัจจุบันยังเก็บและตรวจรหัสผ่านแบบข้อความ ต้องวางแผนอัปเกรดเป็น password hashing โดยรักษาการเข้าสู่ระบบของสมาชิกเดิม
- ข้อมูล SQL เต็ม รูปสมาชิก รหัสผ่าน และไฟล์สำรองเป็นข้อมูลภายใน ห้ามเผยแพร่ใน repository สาธารณะ

## สถานะติดตั้ง

branch `main` ใช้ repository `0tyght/IQSTRC` เป็นแหล่งอ้างอิง รอบนี้ปรับช่องคณะใน localhost และ P&T Hosting เดิม โดยไม่ได้แก้ฐานข้อมูล P&T หรือเซิร์ฟเวอร์ ศจย. ก่อน deploy ครั้งต่อไปควรสำรองฐานข้อมูล/ไฟล์/รูปบน P&T และใช้ค่าการเชื่อมต่อที่ผู้ดูแล P&T ยืนยัน ห้ามนำ credential ขึ้น Git
